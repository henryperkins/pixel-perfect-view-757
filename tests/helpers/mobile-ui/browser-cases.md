# Mobile member flow browser checks

The fixture renders the application's real routes, Shell, styles, controls, draft controller and encrypted IndexedDB store. Authentication, member records, geocoding responses and server mutations are synthetic. It never reads `.env` or calls a model, billing, email or member backend. Google Fonts is loaded for representative typography. Results establish **Render**, not **Device**, evidence.

Start from the repository root with the existing installed dependencies:

```sh
node scripts/mobile-ui-fixture.mjs
```

Open `http://127.0.0.1:4198/`. `PATTERN_MOBILE_UI_PORT` can select another port; update the probe URLs to match. The fixture cache is local to `.playwright-cli/vite-cache`. Stop the server with Ctrl-C. Production bundles do not import this fixture.

Use an available Playwright CLI session in Chromium and another in WebKit. In the Codex environment, the existing wrapper is `/home/ubuntu/.codex/skills/playwright/scripts/playwright_cli.sh`; no project dependency was added. Open each session with its available engine configuration, then run these functions in order:

```sh
playwright-cli -s=mobile-chromium open http://127.0.0.1:4198/
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/store.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/review.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/core.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/advanced.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/layout.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/today.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/today-forms.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/today-overlays.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/today-scroll.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/journal-scroll.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/secondary.cases.txt
playwright-cli -s=mobile-chromium run-code --filename=tests/helpers/mobile-ui/pattern-evidence.cases.txt
```

The `.cases.txt` files contain the async function accepted by Playwright CLI `run-code`, rather than Node test modules. Use the wrapper in place of `playwright-cli` if it is not on PATH. A CLI success exit alone is insufficient: inspect every returned `passed`, any `error`, overflow dimensions, font measurements, focus bounds and reduced-motion result. `core` resets only the synthetic `mobile-audit-member` draft records and fixture session state. Other destructive cases use fresh, isolated browser contexts. Do not run these probes against a member site.

| Probe      | What it establishes                                                                                                                                                                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `store`    | Real IndexedDB/Web Crypto transaction, reopen, account separation, content CAS, two-tab conflict after consent rewrite, expiry, non-extractable key, ciphertext sentinel inspection, damaged-record isolation, consent stripping in values/baseline/submission, and discard/purge while encryption is paused. |
| `review`   | Immediate login cache refresh, root survival with blocked sessionStorage, Today discard, two-tab clear/reactivation, synthetic quota failure, and blocked IndexedDB fallback.                                                                                                                                 |
| `core`     | Today → check-in → save → Journal first at 390×844; navigation/reload, slow save, journal read-only pending fields, lost acknowledgement without duplicate, deletion Back/focus, editor recovery, membership focus, input purposes, selection state and stale geocoding.                                      |
| `advanced` | Uncertain Today save with later edits, dated prior-day recovery, account switching, missing-create retry with original operation, edit retry retaining newer text, failed/pending/direct-link deletion, birth-edit manual coordinates, and focus revalidation without BroadcastChannel.                       |
| `layout`   | Twelve routes × six normal viewports plus three 32 px root-font stress viewports; page width, nav-label overlap, editable text, landscape Timing position, keyboard focus bounds, an unbroken saved URL and reduced motion.                                                                                   |

Normal viewports are 320×568, 360×800, 390×844, 440×956, 667×375 and 844×390. Root-font stress uses 320×568, 390×844 and 667×375. Doubling the root font is not physical-phone zoom. Programmatic Tab and focus bounds do not reproduce an OS virtual keyboard. Real toolbar, safe-area, keyboard/autofill, gesture, VoiceOver/TalkBack and performance qualification remain in the [completion checklist](../../../docs/superpowers/plans/2026-10-14-mobile-member-flow-completion-checklist.md).

The `today-scroll` probe checks empty, short and overflowing notes in portrait and landscape, long/short draft recovery and saved edits, and containment changes after wrapping, rotation and enlarged text without typing. Chromium uses compositor touch input; desktop WebKit uses wheel input at phone dimensions because mobile WebKit does not support Playwright wheel injection. Inspect all eleven results in each engine. These are Render checks; native WebKit swipes, physical-phone pinch zoom, keyboards and browser chrome remain Device checks.

The `journal-scroll` probe applies the same input to the Journal's new-entry and inline-edit bodies: empty, short and overflowing text in portrait and landscape, plus containment that follows growing and shrinking text. Inspect all fourteen results in each engine.

The `secondary` probe covers routes and controls outside the Today flow. Section shortcuts on Today, Context & privacy and the calculator rules must land 8px below the sticky header, or 8px from the top when a short landscape viewport leaves the header in flow; a focusable heading adds its 8px focus margin. Each calculator shortcut must repeat its numbered heading. The Timing filters and reset-password fields must compute to at least 16px. Standalone links must be 44px tall. `/plans` actions must wrap within 320px at a 32px root font, for members and non-members. The account-deletion password field must carry the deletion warning as its description. Inspect all nine results in each engine.

The `pattern-evidence` probe covers the chapter reader and its saved evidence with synthetic narrative, membership and expiry fixtures. It exercises the mounted access lifecycle with controlled request ordering and exact chapter-request counts: cached-preview remounts that unlock or stay locked, both initial response orders, reconciled polls, unavailable writing, explicit retry, retained collapse/reopen, and changed-chart evidence isolation. It also distinguishes server-returned expiry (immediate local preview plus one revalidation) from membership-only deadlines (revalidation without truncation) and an explicit null server expiry (no fallback timer), using Playwright's controlled clock. Membership and narrative failures are injected separately to prove the chapter and its evidence stay visible. Visual cases at 390×844 and 1440×1000 verify paragraph and fact focus outlines after pointer activation, sticky-header clearance, the upsell `h4` at weight 500, and chart-connection `h3` at weight 400 with unchanged serif family and size. A 320×740 case at 200% root text checks toggle wrapping and horizontal overflow. Motion cases count arrival animations once with normal motion and zero with reduced motion, and confirm a retained reopen does not replay them. Today cases check plain accuracy copy, plain degraded-reason copy, missing parent links, and valid versus damaged saved transit sequences. Inspect every result in each engine; a successful CLI exit alone is insufficient.

Besides the member routes, the fixture mounts the public transit chart calculator and the reset-password page (`/reset-password#token=` followed by 64 hex characters shows the form) so `layout` can measure them.

The fixture's synthetic server keeps test records in sessionStorage solely to simulate a server surviving reload. This is separate from production's encrypted IndexedDB draft store. Inspect the latter database for the encryption cases; do not mistake the test backend for production draft persistence.

The `today` probe uses the open fixture's origin and fresh contexts for each regression. It checks all four consent-enabled band groups at normal and enlarged text sizes, taps every value, measures the Sources hit area and narrow save-review action, and confirms that a lost acknowledgement with newer typing exposes recovery beside its status without another write. It also verifies offline submission snapshots and durable later edits, six recovery states at narrow/enlarged sizes, truthful paused statuses with automatic resumption, the selected draft's manual-copy fallback, 48px primary actions, and keyboard focus after saved-value review. Consent withdrawal/re-enablement and discard must invalidate stale queued/copied data. Run all twelve cases in both engines. Geometry checks supplement page-width checks because overlapping choices can remain inside the document width.

The `today-forms` probe walks the real daily check-in and response controls at 390×844 and 667×375: keyboard radio selection, Unicode/multiline typing and correction, failed and confirmed submissions, duplicate Enter suppression, the built-in response retry, Clear selection, draft cancellation/discard, the accessible note limit, and unsaved recovery after reload and document recreation. It checks enlarged-note focus clearance at 320px and exercises constrained-viewport logic with explicitly synthetic geometry in both engines; Chromium additionally supports a page-scale zoom check. These establish Render evidence, not native keyboards, OS background-tab discard, autofill, or screen-reader announcements. The private reflection has no identity/address autofill token; `autocomplete="off"` is intentional. Return remains a newline in the textarea, with a separate guarded form submit action.

Two storage-failure cases throw from the native IndexedDB result getter at the owner-record boundary, during recovery and live editing. The form must settle into its existing storage-unavailable warning, retain current text, allow account submission, and avoid an unhandled page error. These are explicit fault injections; they do not establish the incidence or device cause of a browser deserialization exception.

The `today-overlays` probe checks navigation Close, Escape, Back, current/destination links, reload and Forward, including focus that has moved outside the non-modal disclosure and a newer focus action during history traversal. These dismissal and history cases run in portrait and landscape; the outside-pointer case uses portrait, where background content remains visible. It measures menu-end and Close reachability at normal and enlarged text sizes, verifies valid long content-version reflow with semantic source records, and confirms that inline source/timing disclosures do not consume overlay history entries. A desktop More case protects the shared hook. Chromium additionally exercises wheel containment; mobile WebKit does not support Playwright wheel injection. Native Android Back, iOS gestures, touch overscroll, browser chrome, safe areas and screen readers still require Device testing. The probe uses only synthetic services; it never signs out or accesses a real account.

Request counts and storage fault results are synthetic; LCP, INP and CLS are **not measured** by these probes.
