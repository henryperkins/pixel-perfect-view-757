# Reading evidence save recovery

The Today request could calculate and compose a reading, then fail while saving its evidence. Natal origins and consented context added enough `reading_sources` rows to exceed Cloudflare D1's [100 bound parameters per query](https://developers.cloudflare.com/d1/platform/limits/). Each row has six supplied fields and one generated ID. The local SQLite test database did not enforce that D1 limit, so earlier local reading checks passed. Earlier production release checks covered chart and episode calculation; they did not exercise a complete Today save with this larger evidence trail.

A fresh synthetic production account first created and reopened a smaller reading successfully. After enabling warm tone/context and choosing another invented birth time so a natal lens qualified, its Today request failed with `Reading sources could not be saved. Please retry.` A separate read-only D1 query with 101 synthetic parameters returned `too many SQL variables`. No real birth details or member prose were used in these reproduction cases or included in this evidence.

The evidence save now inserts at most 14 rows per statement, using at most 98 parameters. It keeps every source row and the same expected total. If any chunk fails, the existing cleanup removes that new reading; its evidence rows cascade away. Earlier readings and their evidence remain intact. The member's birth chart and saved content do not need another recalculation for this correction.

Both regression tests failed before the change and pass afterward. They cover successful complete provenance plus cache reopening under the 100-parameter limit, and a later-chunk failure that cleans up the partial new reading while preserving an earlier reading. All **536 application tests**, typecheck, scoped lint and build pass. The harness fault hook now receives parameter arrays so these tests can enforce the production limit. A pre-existing helper signature was formatted to satisfy the changed file's lint check.

The reading language gateway returned its closed credit-unavailable result during the synthetic live calls, so the application used its published template. This recovery does not establish new model generation; the provider fallback is distinct from the evidence-save failure. Publication and the corrected live Today save/reopen will be added after the production check.
