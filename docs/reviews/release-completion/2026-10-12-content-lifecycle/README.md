# Draft review and release lifecycle

Tasks 9–10 freeze the complete baseline when a draft is generated. Comparisons cover every field, section presence, container type and relative array order. Approval binds exact baseline/candidate hashes; editing, regeneration or explicit rebasing clears it. Legacy drafts show an unavailable original comparison until explicit rebase. Desktop columns and labelled mobile blocks retain full text and unchanged context, render untrusted copy literally, and preserve failed edits.

Admin drafts and signed ingestion share immutable numeric staging and expected-pointer activation. The pointer and audit commit atomically, including draft consumption. New canonical SHA-256 checksums are labelled; legacy checksums keep their original values and semantics. Public uploads still activate by default and support inactive staging. Activation/rollback preserves all saved reading history. Delivery writes immutable editorial bundle/operation artifacts, fences the edge mirror against the authoritative pointer and reports incomplete or superseded operations. Reconciliation reuses the operation; a late failure cannot downgrade a successful receipt. No model or calculation runs during publication.
