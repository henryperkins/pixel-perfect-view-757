# Interface clarity review — 2026-10-21

## Scope and decision

Branch: `clarify/interface-clutter`, based on `4897190` on `main`.

Keep Pattern’s existing scientific-editorial identity. Prioritize the daily reading,
its limitations and timing, optional reflection, and returning to one’s own record.
Remove repeated explanation and implementation detail rather than adding another
visual system. Keep deeper tools and account settings reachable through the Shell.

This is an interface cleanup, not a change to astrology calculations, cycle ranking,
model prompts, generated prose, storage, retention, billing, or consent policy.

## Deliberately retained

- Technical values that explain a calculation, and exact saved reference versions.
- The distinction between a supplied/cited reference and proof of every sentence.
- Numerical tolerance versus personal timing accuracy; sampled birth-time ranges
  versus a verified time; unreliable houses versus suppressed angles.
- Consent, retention, provider/data flows, inference risks, exports, deletion,
  assistant-copy limits, and consequences of account or membership changes.
- Account-security and assistant-authorization recovery copy. Email confirmation,
  password recovery and the separate assistant sign-in were source-reviewed, not
  redesigned.
- Administrator measurement/evaluation methodology, spending limits and downloads.
  These are operational tools, not reader-facing decoration.
- Marked-moment creation in Privacy: its life-area choices differ from Journal’s.
  Consolidating those forms would change a workflow, beyond this cleanup.

## PR review follow-up

The review identified four places where simplification removed information needed
to identify saved context or make a permission decision. The follow-up restores:

- Readable window labels derived from saved journal keys when today's windows no
  longer match, and a saved-key fallback for missing chapters. Unknown window keys
  remain identifiable. A historical title or sign is not invented from a key that
  did not record it.
- Full client identifiers beside active and remembered assistant approvals, also
  included in the accessible names of their revocation and clearing buttons.
- Distinct reader-facing reference numbers on daily and natal citation links and
  their matching fact headings. Saved targets and evidence remain unchanged.
- Plain-language permitted uses beside every source, included in each optional
  switch's accessible description. A shared phrase is used only when it is true
  for every source that performs that use. Timezone permission names the local
  day, location names daylight calculation, and check-ins and marked moments do
  not claim to choose reflection questions. Feedback personalisation is not
  described as a preference.

These are interface changes. Calculation, permission enforcement, storage, provider
selection and assistant revocation behavior retain their existing contracts.

Follow-up validation: nine rendered regression tests were observed failing before
their corresponding fixes. The final `npm test` run passed **1,232 tests**, with
**4 existing skips and 0 failures**; TypeScript, the production build, changed-file
ESLint and `git diff --check` passed. A later review found that those shared labels still overclaimed timezone,
location, check-in, and marked-moment uses. The sentences now name only the uses
each source performs. That correction was checked with `npm test`: **1,235 passed,
4 skipped, 0 failed**. ESLint passed on the privacy route and its render test.

Chromium checks covered Journal, Assistants, Privacy, daily references and natal
references at **1280 × 900** and **390 × 844**, plus Privacy at 200% root text size.
The eleven rendered-state checks found no page overflow or runtime errors. They
also checked long client IDs, the selected client's clearing request, matching
citation headings and focus moving to the selected saved fact. All services and
content were synthetic. Evidence is in `/tmp/pattern-pr2-fixes-browser/`; no live
provider, OAuth approval, payment or physical-device behavior was qualified.
