# Context-aware daily writer candidate

The user approved implementation of a context-aware writer and benchmark readings for selected natal context, transit context and both. The goal is one recognizable, useful thread in the observational voice, with each source condition and calculated chronology intact. This is an inactive synthetic candidate; publication, member activation and a paid provider pilot are separate work.

## Design

- Keep the production `0.9.0` member path and its limited authored catalogue intact.
- Add an explicit opt-in to the existing server-only synthetic writer. The candidate shares the gateway, whole-draft factual checks and failure handling, with distinct prompt and validator identities.
- Project one source-bound brief: primary interpretation, any synthesis and its parents, selected natal distinction, selected transit chapter and exact chronology. Meaning appears once; source identity, controls and measurements are separate. Private reliability evidence, local context, recent writing and legacy auxiliary prose do not cross the provider boundary.
- Apply the observational voice independently of tone and depth. Standard permits the required literal chronology; technical may add only supported calculation details. No new natal geometry or planetary symbolism is authorized by a writing change.
- Supply independently authored headlines, reflections and complete cited fallback readings. Bind each benchmark to the exact selected source graph; reject a mismatched or invalid fallback before a provider request.
- Preserve source parent coverage, natal conditionality, synthesis coverage and the exact chronology in the first two paragraphs. Do not rewrite saved readings or weaken the established validators.

## Implementation and acceptance

1. Freeze a five-case comparison from one existing synthetic Saturn-square-Sun fixture: contact only, natal only, transit only, both, and synthesis with both. Record source/config identities and authored copy.
2. Write failing source-projection and writer tests. Implement the source brief and candidate opt-in without changing default callers.
3. Exercise accepted and rejected drafts through the real shared gateway/validator boundary with intercepted transport. Verify one attempt, complete fallback, independent headline/reflection validation and honest diagnostics. Exercise all tone/depth combinations and suppressed geometry.
4. Render an auditable benchmark packet, inspect independent editorial/source review, and correct substantive findings. Keep authored benchmarks distinct from actual model output and human approval.
5. Run focused tests, the repository test suite, TypeScript, scoped lint and build. Record exact artifacts and remaining qualification work. Make no production or paid requests in this implementation task.

Success means a runnable candidate and source-checked benchmark pack, with no lost natal or transit context and no production route change. Structural tests and assistant editorial review do not establish future provider quality or member benefit.
