## Detector and critique integrity

Read the installed critique procedure before using it. Where it calls for independent agents, use actual separate assessments when the host permits them; otherwise disclose its documented fallback. Follow the current host's permissions rather than assuming an old version's extra approval gate. Assessors given earlier findings are not independent of those findings.

Use existing detector/hook output and avoid redundant runs. Verify detector findings in context, including legitimate target-size exceptions, supported-browser behavior, and the distinction between an ergonomic recommendation and a WCAG failure. Preserve raw scores and any explicit translation into the runner's P0–P3 impact definitions; do not add unrelated scores together. A detector's finding exit code is not necessarily a tool crash; consult the installed implementation.

Only claim browser overlays, snapshots, trend writes, or critique closure when those operations actually succeeded and were authorized. Retain the precise snapshot identity for any closure. Unresolved findings remain in the audit even if a separate presentation snapshot changes.
